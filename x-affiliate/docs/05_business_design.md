# STEP 5：事業設計（ミモザデータ）

## コンセプト

**「女性の働き方を、数字で選ぶ。」**
企業が法律にもとづいて公表している数字（男女の賃金差異・女性管理職比率・男性育休取得率など）を、出典つきで読み解くデータメディア。フェミニストの価値観は「主張」ではなく、**女性が不利になりやすい構造を数字と制度で可視化する編集方針**と、**商品選定の基準（女性の働きやすさを確かめる手段になるか）**として表れる。

## ファネル（放置しやすく、積み上がる構造）

```
            ┌──────────── X（集客：1日2投稿、自動予約投稿）─────────────┐
            │  A/B/C 投稿：数字・読み方・制度（リンクなし、価値完結）       │
            │  E 投稿：記事の要点 → 自分のリプ欄にリンク（#PR）           │
            └───────────────┬───────────────────────────────┘
                            ▼ プロフィールリンク／リプ欄リンク
  ┌────────────────── Webサイト（独自ドメイン・静的サイト）──────────────────┐
  │ ① 解説記事（読み方・見分け方・面接の質問・制度）……信頼をつくる            │
  │ ② 業種別データページ（中央値・上位企業）……「自分の業界は？」の受け皿     │
  │ ③ 企業データページ（最大3,000社）……企業名で調べる＝最も購買意欲が高い層   │
  │ ④ 比較・選び方記事（エージェント／コーチング／本）……成約ページ            │
  └───────────────┬──────────────────────────────────────┘
                  ▼ 文脈に沿ったCTA（「口コミも確認」「担当者に実態を聞く」）
         ASPリンク（rel="sponsored"）→ 登録・面談予約・購入 ＝ CV
                  ▲
  Google 検索（企業名＋賃金差異／業種＋女性管理職 など）── ③②が自動で受ける
```

### なぜこの形が「放置しやすい」か

| 要素 | 放置性の理由 |
|---|---|
| 企業・業種データページ | 月1回のデータ再取得で自動更新。人が書く文章はテンプレートのみ |
| 解説記事 | 制度・読み方は数年単位で陳腐化しにくい（法改正時のみ更新） |
| X投稿 | 週1回のPRマージで1週間分が自動投稿 |
| CTA・リンク | `data/links.yaml` 1か所の差し替えで全ページに反映 |

### なぜメール/ニュースレターを最初に入れないか

ニュースレターは購読者との関係が強い一方、毎週の執筆・配信が「労働」になりやすい。サイトの `feed.xml`（RSS）を用意してあるので、**フォロワー3,000人到達後**に RSS→メール自動配信（Buttondown / beehiiv などのRSS取り込み）を追加する（作業時間は増えない）。

## コンテンツの3層

| 層 | 例 | 目的 | 生成 |
|---|---|---|---|
| 1. データ | 業種別中央値、企業ページ | 検索流入・独自性 | スクリプトで自動 |

| 3. 送客 | エージェントの選び方、コーチングの使い方、本 | 成約 | Claude下書き→PRで承認 |

## 商品選定の基準（ペルソナの価値観を基準として明文化）

紹介するのは、**読者が「女性の働きやすさ」を自分で確かめる手段になるもの**だけ。

1. 求職者が無料で使える、または費用・解約条件が明確
2. 企業の実態（育休復帰、評価、働き方）を確認する手段になる
3. 「稼げる」「年収が上がる」など誇大な訴求を広告主が求めない
4. 女性の選択肢を狭める・不安を煽るものは扱わない

## 収益目標（現実的なライン）

| 時期 | 目標 | 主なドライバー |
|---|---|---|
| 1〜2か月目 | ¥0〜3,000 | ASP提携、本の紹介、データページ公開 |
| 3〜6か月目 | ¥10,000/月 | フォロワー3,000人、記事20本、企業ページの検索流入開始 |
| 6〜12か月目 | ¥30,000〜50,000/月 | フォロワー1万人、記事50本、検索流入がX流入と同程度に |
| 12か月〜 | ¥100,000/月を狙う | 検索流入の積み上がり＋RSS→メール導入 |

## KPIツリー（最重要KPI＝期待利益÷オーナー作業時間）

```
期待利益/時間 = (確定報酬 − コスト) ÷ オーナー作業時間
  確定報酬 = サイト訪問 × アフィクリック率 × 成果率 × 平均報酬（承認後）
    サイト訪問 = X経由（インプ × リンクCTR） + 検索経由（ページ数 × ページ当たりPV）
  オーナー作業時間 = 週次PR確認（目標15分）+ 月次ASP作業（目標10分）
```

週次レポート（`analytics/reports/`）が X 側の指標を、`analytics/kpi_monthly.csv` が報酬と作業時間を追う。
